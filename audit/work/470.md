# #470 Падение корзины героев у администратора (+#472 тот же стек)
Пакет: 1 Падения и связь; статус: решено; сервер: да; дизайн: нет

## Разбор
Причина: ModerationService.delete(HERO) без блокировки и проверки «уже удалён» -> две санкции удаления одного героя; корзина отдаёт строку на санкцию, ключ строки = id героя (ModerationClient.kt:132, ModerationPage.kt:121) -> дубль ключа LazyColumn. Подробно: triage/moderation.md.

## Вопросы и ответы
1. Чистка повторов в базе: авто при старте (рек.) / только клиент / скрипт. Ответ: авто при старте - идемпотентно, оставить раннюю санкцию.
2. Одновременное удаление: второму успех без действия (рек.) / отказ «Уже удалён». Ответ: успех без действия.
3. #472: главный #472, оба закрываются коммитом (рек.) / #472 duplicate. Ответ: оба Closes, без duplicate.

## Решение
Сервер: удаление под блокировкой героя, повтор - идемпотентный успех; разовая чистка дублей санкций при старте. Клиент: ключ строки корзины = id санкции, дедуп внутри страницы. Closes #470, #472.

## План и коммиты
Сервер: удаление героя под замком героя (аккаунта - под замками его героев), повтор - успех без новой санкции; на старте лишние действующие удаления одной цели закрываются (остаётся раннее), тест SurplusDeletionsTest. Клиент: ключ строки корзины - id санкции удаления, дедуп внутри страницы и на стыке (TrashKeysTest).
