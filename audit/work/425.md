# #425 [Баг] Во всех пролистываемых списках проверь работает ли пагинация - должна, так же это должно работать корректно и со всеми …
Пакет: Отчёты; статус: решено; сервер: да; дизайн: нет

## Разбор
Причина: admin/feedback без страниц, всё в память (FeedbackService.all :172), клиент фильтрует; known - только страница 0 по 100 (FeedbackClient.kt:28); журнал модерации угадывает число страниц.
Предложение: Серверная страница admin/feedback с очередью/поиском/сортировкой/счётчиками; known - страницы; журнал - total. 10-15 ч.

## Вопросы и ответы
1. Какие списки? Ответ: все сломанные серверные (очередь модерации, журнал модерации; Известные - удаляются).
2. Вид листания? Ответ (свой): автоподгрузка следующей страницы при листании вниз.
3. Где? Ответ: везде - один общий компонент: очередь и журнал модерации, модерация игроков, корзина, поиск и журнал гильдии, витрина и торги Рынка (вместо «Показать ещё» и Pager).
4. Размер подгрузки? Ответ: 30, одно число в правилах контента.
5. Счётчики? Ответ: с учётом поиска; смена фильтра/поиска/сортировки - с первой страницы.
6. Известные? Ответ: удалить целиком - вкладку, маршрут bugreport/known, поле known, ключи, строку RULES.md.

## Решение
Сервер: admin/feedback?kind&queue&q&sort&page -> страница + total + счётчики очередей; журнал модерации с total/hasMore; единый размер страницы в rules; удалить known. Клиент: общий компонент автоподгрузки (LazyColumn + порог), перевести все серверные списки.
