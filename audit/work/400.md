# #400 Назойливое требование обновиться во время забега
Пакет: Забег и обновление; статус: решено; сервер: нет (опц. поле в update.json); дизайн: один компактный тост

## Разбор
Суть: плашка `UpdateHint` висит весь забег (`UpdateDialog.kt:167-176`), сразу после закрытия захода - модалка без закрытия (`:43-55`); любой новый versionCode считается обязательным (`Updates.kt:52-64`, `UpdateModel.kt:46`).
Причина: нет различия жёсткого (провод сервера новее, 426) и мягкого (тот же API_REVISION/RULES_VERSION) обновления, хотя `WireFit` (`StartGate.kt:12-26`) данные даёт. Модерация: «обычно обновление = сервер = механики».
Предложение: 5а (рекомендую) - `AvailableUpdate.hard = outdated || провода расходятся`; жёсткое - как сейчас; мягкое - один тост за сессию с «Обновить»/«Позже», без модалки; 5б - рычаг `mandatory` в update.json (android.yml:485-499) для объявления мягкого релиза жёстким. Альтернативы: 1 плашка на N секунд; 2 не показывать в забеге; 3 «Позже» на N минут для всех (опасно при 426); 4 баннер для всех (противоречит модерации).

## Вопросы и ответы
1. Мягкое обновление (тот же провод)? A (рекомендовал) один тост за сессию «Обновить»/«Позже», без модалки, в забеге не показывать / B тост при каждом холодном старте / C только карточка в настройках. Ответ: A
2. Жёсткое в забеге? A (рекомендовал) плашка 10 с, потом значок у меню забега; модалка после забега остаётся / B как сейчас. Ответ: A
3. Рычаг «релиз обязателен»? A (рекомендовал) поле mandatory в update.json из трейлера коммита `Update-Mandatory: yes` (android.yml) / B minClientBuild в манифесте сервера / C нет. Ответ: A
4. Повтор мягкого тоста после «Позже»? A (рекомендовал) до следующего холодного запуска / B 6 ч / C 1 ч. Ответ: A

## Решение
Макет: mock_400.html, вариант A (тост снизу над панелью вкладок; в забеге плашка у низа карты 10 с, сворачивается в кружок у кнопки меню забега). Текст жёсткой плашки: «Сервер обновлён. Поход продолжится после обновления игры до {0}».
AvailableUpdate.hard = outdated || провод сборки != провод сервера || update.json.mandatory. Жёсткое: плашка в забеге 10 с → значок у меню забега; модалка после забега как сейчас. Мягкое: один тост за процесс с «Обновить»/«Позже», не в забеге; карточка в настройках остаётся. android.yml: поле mandatory в update.json из трейлера `Update-Mandatory: yes` финального коммита. Макет: тост и свёрнутый значок - 3 варианта.
