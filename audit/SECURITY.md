# Безопасность, целостность состояния, экономика

Все проверки - на локальном сервере (сборка ветки, тестовые базы `auditdb`/`probedb*`/`loaddb*` в одиночном replica set
MongoDB 7.0.14 на `127.0.0.1`), тестовые аккаунты сида и аккаунты по устройству. Production не трогался.

## Механизмы, на которых держится целостность (проверено чтением и пробами)

- Оптимистичная блокировка: `Hero`, `User`, `Guild`, `AuctionLot`, `Mail`, `Sanction`, `BugReport` пишутся с фильтром `_id + version`
  (`base/repository/Versioning.kt`); несовпадение - `BRY_002`, транзакция откатывается. Поэтому снимок, прочитанный вне замка,
  не перезапишет чужую правку.
- Многодокументные изменения - одной транзакцией (`transactionExecute`): покупка лота (покупатель + продавец + лот), забор
  вложения (герой + письмо), склад гильдии (гильдия + герои), снятие лотов при переносе и самоудалении.
- Условные записи: промокод (`claimRedemption` с `$ne`), Предначертание, привязка логина.
- `HeroLocks` - очередь запросов одного героя в процессе; ключ - герой, проверенный `HeroGate`, а не сырой параметр.
- Владение: `HeroGate` сверяет `heroId`/`id` с аккаунтом и санкциями до маршрута; `itemId`, `petId`, `questId`, `offerId` ищутся
  только в документе героя; `lotId` - тот же `server` и не свой; письмо - `userId` и `heroId` (ML_007).
- Игровые серверы: фильтр `server` есть на аукционе (`search`, `buy`, `priceHint`), гильдиях (`search`, `join`, `apply`,
  `invite`, `joinByCode`, `acceptInvite`), почте (`Courier`, `ignore`).
- Модерация (`ModerationPolicy`, `AuthTest` - 18 тестов зелёные): администратор неприкосновенен; модератор банит игроков и
  тестировщиков; модератора банит и удаляет только администратор; бан устройства, удаление, восстановление - администратор.
- Обход политики через `//` и `%XX` не проходит: `AccessPolicy.canonical` строже маршрутизатора Ktor.
- Секреты: только из окружения (`Constants.kt`), дефолтов секретов нет; в JSON и workflow секретов не найдено.
- Лимиты частоты: вход 10/мин по адресу, устройство 60/мин, промокод и код гильдии 5/мин, общий 600/мин на аккаунт.

## Подтверждённые дефекты

### SEC-1 · P2 · ИСПРАВЛЕН - покупка лота героя под санкцией по прямому id

- ktor-bestgame `features/logic/trade/AuctionService.kt` (`buy`). `search` прячет лоты героев из `sanctions.hiddenHeroes()`,
  `buy` санкции продавца не проверял: зная `lotId`, сообщник выкупал лоты забаненного - канал вывода ценностей.
- Проба S8 до правки: `FAIL (bought)`; после: `PASS (AU_004)`. Регрессия: `ServerIntegrationTest` (бан героя-продавца → `AU_004`).

### SEC-2 · P2 · ИСПРАВЛЕН - купленная вещь при полном тайнике уходила торговцу (потеря ценности)

- ktor-bestgame `AuctionService.deliver`, `MerchantService.buy`, `MerchantService.trophy` → `Stash.receive`, который без места
  продаёт вещь торговцу. Покупатель платил сферы и комиссию / золото с наценкой / трофеи, а получал золото цены торговца.
  KDoc `Stash.fits`: «покупка без места - отказ, а не продажа».
- Исправление: `Stash.requireRoom` (отказ `CH_020`, локализован) до списания в трёх путях; `CraftsService.release` возвращает
  удерживаемую вещь Осквернения через `Stash.giveBack` (своя вещь торговцу не уходит).
- Проба S6 до правки: `FAIL (bought and sold to the merchant)`; после: `PASS (CH_020)`. Регрессия: `ServerIntegrationTest`.

### SEC-3 · P2 · ИСПРАВЛЕН - ложный успех повтора команды по `Idempotency-Key`

- ktor-bestgame `config/MongoFactory.kt` (`transactionExecute`), `IdempotentReplyStore`.
- Метку «команда исполнена» вешала **любая** транзакция в контексте команды, в том числе побочные до основной записи:
  `expireDue`/`reconciled` в покупке лота, досчёт ремесла `settle` в `crafts/start|stop`, `GuildAccess.heal`. Если затем падала
  основная запись (частый случай - `BRY_002`: версия продавца ушла вперёд, он в этот момент играл), ключ оставался «исполненным»,
  и повтор клиента получал `{"success":true,"data":null}` с `Idempotent-Replay: true` - покупка не прошла, клиент считает, что прошла.
- Исправление: `MongoFactory.aside { }` - побочная запись без метки; через неё идут обслуживание лотов (`quietly`), досчёт ремесла,
  `GuildAccess.heal`. Основная запись метку несёт как раньше.
- Регрессия: `CommandMarkTest` (добавлен в фильтр `deploy.yml`). Сквозное воспроизведение гонки `BRY_002` не автоматизировано.
