# #400 Назойливое требование обновиться во время забега
Пакет: Забег и обновление; статус: разбор; сервер: нет (опц. поле в update.json); дизайн: один компактный тост

## Разбор
Суть: плашка `UpdateHint` висит весь забег (`UpdateDialog.kt:167-176`), сразу после закрытия захода - модалка без закрытия (`:43-55`); любой новый versionCode считается обязательным (`Updates.kt:52-64`, `UpdateModel.kt:46`).
Причина: нет различия жёсткого (провод сервера новее, 426) и мягкого (тот же API_REVISION/RULES_VERSION) обновления, хотя `WireFit` (`StartGate.kt:12-26`) данные даёт. Модерация: «обычно обновление = сервер = механики».
Предложение: 5а (рекомендую) - `AvailableUpdate.hard = outdated || провода расходятся`; жёсткое - как сейчас; мягкое - один тост за сессию с «Обновить»/«Позже», без модалки; 5б - рычаг `mandatory` в update.json (android.yml:485-499) для объявления мягкого релиза жёстким. Альтернативы: 1 плашка на N секунд; 2 не показывать в забеге; 3 «Позже» на N минут для всех (опасно при 426); 4 баннер для всех (противоречит модерации).
