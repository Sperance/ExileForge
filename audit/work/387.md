# #387 Единый стиль окон поиска и фильтров
Пакет: Поиск и выбор; статус: решено; сервер: нет; дизайн: да

## Разбор
Суть: везде один компактный поиск с подсказкой по контексту и кнопкой фильтра; расширить фильтры.
Причина: общий CompactSearchField (ui/components/CompactSearch.kt:39) есть, но используется в 2 местах (GuildScreen:131, GuildRoster:111). ~12 мест в 4 стилях: OutlinedTextField + ForgeButton (AuctionShowcase:183, GuildStash:196), поиск только в шторке ItemFilterBar (StashPane:99, TargetPicker:51, MerchantTab:106), свои поля (TreeSearch:117, Feedback:186, ModerationPage:79, AdminFeedback:87, Spinner). Кнопки фильтра трёх видов.
Предложение: общий SearchBar = CompactSearchField + очистка + слот кнопки фильтра (ItemFilterButton с числом) + слот действия; внедрять волнами (игровые экраны, потом админка). ~10-15 ч.

## Вопросы и ответы
1. Поле поиска на экране тайника/кузницы/торговца. Ответ: да, везде на экране - одна строка «поиск + фильтр» вместо полосы-сводки (рекомендовал).
2. Админка и модерация. Ответ: да, все экраны (рекомендовал).
3. Каких фильтров не хватает (мульти). Ответ: «лучше надетого», «требуемый уровень / можно надеть», «по моду» (выбор стата из списка с поиском).

## Решение
Общий SearchBar (CompactSearchField + очистка + кнопка фильтра с числом + слот действия), подсказка по месту; внедрить на всех экранах (игровые, модерация, админка). Новые грани ItemFilter: лучше надетого, можно надеть (требуемый уровень), по моду. Макет mock_387.html (scratchpad), выбран вариант A: поле поиска во всю ширину (подсказка по месту, ✕), справа снаружи кнопка фильтра с числом и кнопка порядка/«+»; под полем ряд чипов включённых сужений с ✕ и «Сбросить», только когда сужения есть (пилюля уровня «Ур. 27–37» - один из чипов).
