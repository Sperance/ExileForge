## Задача 5 — GitHub Issues вместо Asana (добавлено владельцем)
Все решения — строки GH-ISSUES* и ASANA-REMOVE в /home/user/audit/16_DECISIONS.md (прочитай дословно). Кратко:
- Отчёт после модерации (переход в «Отправлен») создаёт Issue в Sperance/ExileForge (репо ПУБЛИЧНЫЙ): метки bug | enhancement + from-game; в теле только техническое (текст, экран, версия клиента, ошибки запросов, уровень/класс героя, номер отчёта). IP, аккаунт, id, устройство, имя героя — НЕ в Issue.
- Скриншоты в отчётах убрать полностью (клиент и сервер, квоты).
- Сервер раз в ~10 мин опрашивает GitHub REST (Issues с from-game, since) и обновляет статусы отчётов: «В работе» (открыт) / «Исправляется» (метка in-progress) / «Исправлено в X»/«Сделано в X» (закрыт выполненным, версия — из комментария/метки релиза) / «Не будет сделано» (wontfix + причина) / «Дубль» (duplicate); последний комментарий — ТОЛЬКО от владельца/коллабораторов (author_association OWNER/MEMBER/COLLABORATOR).
- Голоса за предложения продолжаются в игре, пока Issue открыт; сервер обновляет в теле Issue строку «Голоса игроков: +N / −M».
- Токен: секрет ktor-bestgame GH_ISSUES_TOKEN (fine-grained, Issues RW на ExileForge) → deploy.yml передаёт на VPS в окружение сервера; без токена — понятный отказ, синхронизация выключена.
- job release в android.yml: после публикации v<версия> закрыть Issues, упомянутые «Closes #N» в коммитах релиза (с прошлого тега), комментарий «Исправлено/Сделано в X» + метка версии (permissions: issues: write).
