История ревизий контракта, версий кода правил и форм коллекций сервера. В коде у констант - только смысл и когда поднимать; история - здесь. Новая строка - при каждом подъёме, в том же коммите.

## Формы коллекций и миграции (`config/CollectionSchemas.kt`)

- `data class CollectionSchema(val name: String, val version: Int, val wipes: List<String> = emptyList(), val fixups: List<` - Форма коллекции (1.80.6). Миграций нет: если документы коллекции старой формы больше не читаются, подними её [version] - при старте (автодеплой) сервер снесёт коллекцию вместе со всеми, что на неё ссылаются ([wipes], транзитивно), и поправит ссылки в уцелевших ([fixups]). Если данные нужно сохранить - это миграция: решает владелец, версию без него не поднимать.
- `data class Fixup(val collection: String, val update: Bson? = null, val prune: Bson? = null) {` - Правка уцелевшей коллекции [collection] после сноса той, на которую она ссылалась: [update] ко всем её документам или (4.12.x, DATA-04) удаление её документов под [prune] - сирот снесённой коллекции, когда остальные документы живут.
- `data class PartSchema( val collection: String, val part: String,` - Часть формы документов (1.81.10): поле коллекции [collection], чьи старые значения больше не годятся, а сама коллекция читается - сносить её не нужно. Смена [version] один раз правит её документы под [filter] (4.6.5; по умолчанию - все): [update] с [arrayFilters]. Запись в `Schema` - под [name] `коллекция.часть`; часть без записи считается версией 0 - новая часть применяется на первом старте.
- `data class PruneSchema(val collection: String, val part: String, val version: Int, val filter: Bson) {` - Срез документов (4.6.5): документы коллекции [collection] под [filter], что больше не годятся, а остальные читаются - сносить всю коллекцию не нужно. Смена [version] один раз удаляет их; запись в `Schema` - под [name] `коллекция.срез`, как у части.
- `enum class FillKind {` - Чем заполняется поле ([FillSchema]): [SHORT_CODE] - свой короткий номер каждому документу ([ru.descend.exileforge.base.repository.ShortCodes]). - `KEY_COUNT,` - Число ключей объекта-поля [FillSchema.source] документа (4.10.x): выводимый размер карты - одной записью на стороне базы.

Запись в `Schema` - под [name] `коллекция.поле`, как у части.
