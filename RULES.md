# RULES.md - правила ExileForge (клиент)

Дополняет `CLAUDE.md`; при противоречии `CLAUDE.md` главнее. Читай в начале каждой задачи. Раздел «Общее» одинаков с `RULES.md` сервера ktor-bestgame - правь оба.

## Общее (сервер и клиент)

### Игровые инварианты
- Любая сущность с редкостью (предмет, питомец, всё новое) держит дно и потолок модификаторов из `content/rules.json` → `rarities` на каждом пути: ролл, сферы, ремесло, торговец, разведение, старые данные. Если дно удержать нельзя - понижай редкость, пустым не оставляй.
- Каждый модификатор всех пулов (предметы, монстры, карты, Атлас) локализован на всех языках на сервере и в клиенте; при добавлении или правке модификатора проверяй это.
- Каждый предмет (экипировка и сумка) имеет свою иконку; у уникального и мифического - свой спрайт, не общий ни с кем. Каждая характеристика героя (группы HERO, BATTLE, FLASK, AURA) - своя уникальная цветная GLASS-иконка. Проверяет `IconsTest` сервера.
- Ни одного балансного числа в Kotlin: шансы, веса, цены, лимиты, таймеры, коэффициенты - только в `content/*.json` с типизированным чтением (`EngineRules`, теги `tables.json`). Нашёл число в коде при правке - вынеси.
- Всё, что даёт ценность (лут, опыт, золото, предмет, питомец, валюта), роллится детерминированно в `rules/` через `Dice`/seed и подтверждается сервером. Бой считается на клиенте (`core/campaign/combat/`, забег - `core/campaign/run/`), сервер проверяет правдоподобие лога событий.
- `rules/` - чистый JVM: без Ktor, Mongo, Android, без `kotlin.random.Random` мимо `Dice` и без `System.currentTimeMillis`. Сервер и клиент не дублируют и не «подправляют» его результат.
- Стадия альфа: совместимость со старыми сохранениями не обязательна - при несовместимой схеме база сбрасывается; миграции и ремонт «ради старых данных» не пиши.

### Локализация
- Ни одной строки для игрока в Kotlin - только словари (`ui()`/`loc()` в клиенте, `LocaleKey` на сервере). Исключение: бренд и отладочные экраны.
- Оба словаря (сервер `locale/*.json`, клиент `ui_*.json`) правь сразу на всех языках в одном коммите; `LocalizationTest` и `UiStringsTest` зелёные.
- Новый язык - только полным комплектом: сервер `locale/<lang>.json` + `index.json`, клиент `ui_<lang>.json` + `enum Lang`.
- Новый код ошибки (`funException*`, `RuleViolation`) - с локализацией на всех языках.

### Версии и релиз
- Семвер: по умолчанию поднимается только patch (третье число) - любое изменение; minor и major - только после вопроса владельцу и его согласия. Несколько изменений в одной задаче - один подъём.
- Задача на оба репо: сначала сервер (коммит, пуш), затем в той же задаче клиент закрепляет его - сабмодуль `backend/`, `SERVER_COMMIT`/`SERVER_VERSION` в `Contract.kt`, `API_REVISION` в `Sync.kt`. Пока клиент не закрепил новый сервер, задача не закрыта.
- Коммиты по-английски, Conventional Commits. Комментарии и KDoc по-русски; старые не переписывать.
- Источник правды - код и KDoc. Доки, дублирующие код (контракт API, описание CI), не заводить.
- README дополняется только при изменении жёстких механик.
- Перед пушем гоняй только тесты, затронутые изменением: контент/локаль → `LocalizationTest`, `ContentLoadTest`; ролл/сферы → `RulesInvariantsTest`; предмет/стат → `IconsTest`; словарь клиента → `UiStringsTest`. Остальное проверит CI.

### Стиль
- ktlint (`.editorconfig`: `intellij_idea`, без ограничения длины строки) - ворота CI. Перед пушем `ktlintCheck`, форматирование - `ktlintFormat`. Правила в `.editorconfig` не ослаблять без просьбы.

## Клиент

### Версии и релиз
- На каждое изменение: `versionCode` +1 и `versionName` по семверу в `app/build.gradle.kts`; `RELEASE_NOTES.md` перезаписывается заметками только этой версии (`## <versionName>`, по-русски, для игрока; техническое изменение - одна строка). CHANGELOG не ведётся.
- Сервер закреплён трижды и всё меняется вместе: сабмодуль `backend/`, `SERVER_VERSION`/`SERVER_COMMIT`/`SERVER_BRANCH` в `core/contract/Contract.kt`, `API_REVISION` в `core/model/sync/Sync.kt`. Манифест сервера должен совпасть точно.
- Макеты («сгенерируй дизайн») в репозиторий не коммитятся - отдаются файлом.

### Архитектура
- `:core` - чистый JVM: логика, сеть (OkHttp), модели, словари; без `android.*`. `:app` - только Compose и Android; без OkHttp и расчётов.
- Сетевые ошибки - исключения `ApiFailure`, не `Result`. Мутации героя - через `CommandQueue` с `Idempotency-Key`, не напрямую через `Transport`.
- Целевая архитектура: Navigation 3 для экранов (стек `Navigator` принадлежит приложению, ключи `Route` типизированы; фичи не пишут вкладку, а просят навигатор) и Koin для зависимостей. Новые экраны и зависимости - через них. Экран читает срез своей модели (`GameUi` из `GameSlice`, `AccountUi`), общего состояния нет (3.80.41); логика приложения - сервисы `presentation/app` над `AppService` (3.80.44). Hilt не заводить.
- Текст модификаторов - `ModifierText` из `rules` по словарю сервера; своих строк модификаторов у клиента нет.

### CI
- `android.yml`: `:core:ktlintCheck`, `:app:ktlintCheck`, `:core:test`, lint, сборки debug/release/minifiedTest, UI-тесты на эмуляторе, клиент-серверный тест против закреплённого сервера; job `release` публикует `v<versionName>`. После пуша проверь, что релиз появился.
