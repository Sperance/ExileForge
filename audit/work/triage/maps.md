## #460 — Скверна не появилась, хотя её выбрали в «окне модерации»; хаос-сопротивление мобов Скверны

**Суть.** Тестировщик отметил «Скверна» в панели механик перед запуском, а очага на карте не было. Вторая часть: проверить, что у всех монстров Скверны повышено сопротивление хаосу.

**Что это за окно.** Панель тестировщика «Механики · выбрано N» в карточке зоны: `app/.../expedition/ZoneCard.kt:139` (`if (game.freeProgress) TesterMechanics(vm, forced)`), сама панель — `ZoneCard.kt:196-218`, чипы `MapMechanic.entries`. Подсказка `ui_ru.json:29`: «Отмеченное встанет на новый заход **наверняка**: Скверна — все точки и Матерь…». Выбор уходит в `POST /campaign/start?forced=BLIGHT` (`core/.../network/CampaignClient.kt:58` → `HeroRoute.kt:278` → `CampaignService.kt:191,249` → `RunContext.forced`).

**Корневая причина (подтверждена).** `backend/rules/.../run/MapFeatures.kt:449-453`:
```kotlin
if (rule.chance <= 0 || rule.points.isEmpty() || index.campaign.act(zone.code) < rule.fromAct) return null
...
if (!dice.roll(MapMechanic.BLIGHT, run.context, ...)) return null   // forced проверяется только здесь
```
В `campaign.json:10648` `"fromAct": 3`, а зона отчёта `C1_SMUGGLERS_GROTTO` — **акт 1** (проверено по `regions`). Ворота акта стоят ДО броска с `forced`, поэтому насильная Скверна в актах 1–2 молча отбрасывается. То же семейство тихих ворот: `VAAL` только в зонах с `zone.corrupted` (`Run.kt:565`), `ALTAR` — только в заходе по карте-предмету (`MapFeatures.kt:355`, `run.context.active == null → emptyList()`). Клиент об этом не говорит — чип горит, подсказка обещает «наверняка».

**Хаос у мобов Скверны (как сейчас).**
- Состав очага (`Run.kt:626-642`): вожак точки — из `blight.leaders`, прочие жетоны — **обычные монстры зоны** (`dice.pick(zone.monsters)`), Матерь — босс. На всех — печать `BLIGHT_MOB_TAINTED` + пул `mob:blight` (`tables.json:9`).
- Печать `BLIGHT_MOB_TAINTED` (`modifiers.json:96`): больше здоровья, больше урона, +урон хаосом — **сопротивления хаосу нет**.
- Базовые: `BLIGHT_DEVOURER` 40%, `BLIGHT_PROPHET` 50%, `BLIGHT_MOTHER` 60% (`campaign.json:5738-5741`), **`BLIGHT_ROTSTALKER` — 0%**, рядовые монстры зоны — как у зоны (обычно 0).
- Итог: требование «у всех мобов Скверны повышенный иммунитет к хаосу» **не выполнено** для Rotstalker и для всех рядовых жетонов точек.

**Исправлено ли.** Нет (код ветки на 0.17.2; в `git log` правок нет).

**Сервер.** Да — `rules/` (общий модуль; клиент тянет его же, т. к. очаг ставится по семени у обоих) + контент сервера.

**Варианты (баг с forced):**
1. **(рекоменд.)** `forced` обходит «мягкие» ворота: в `blight()` условие акта — `act < fromAct && MapMechanic.BLIGHT !in run.context.forced`. Для невозможных по смыслу (VAAL без порченого монстра зоны, ALTAR без карты-предмета) — чип в панели гаснет с причиной («Нет в этой зоне», «Только с картой»), подсказку `tester.mechanics_hint` поправить. + плюс: тестер может проверять Скверну где угодно; − семя/поток не меняется (бросок всё равно тратится), риск мал. ~1.5–2 ч.
2. Только честность UI: ворота не трогать, чип Скверны в актах 1–2 гаснет «Скверна — с акта 3». + ноль риска для правил; − тестировать в начальных зонах нельзя. ~1 ч.
3. Сервер отказывает старту кодом ошибки (новый `CP_0xx` с локализацией ru/en), если forced-механика невозможна в зоне. + явно; − лишний отказ, тестер теряет вход. ~1.5 ч.

**Варианты (хаос-сопротивление):**
1. **(рекоменд.)** Добавить четвёртый эффект в печать `BLIGHT_MOB_TAINTED`: `STOCK_RESIST_CHAOS` по сетке уровней `bottom [20,25]` → `top [35,40]`, `apex(80) [40,45]` — ложится на всех (рядовых, вожаков, Матерь), т. к. печать принудительная. Шаблоны `modifier.BLIGHT_MOB_TAINTED.name` в `locale/ru.json:8200` и `en.json:8200` дополнить `{3}` («+{3}% к сопротивлению хаосу» / «+{3}% Chaos Resistance») — клиент берёт тексты модификаторов из словаря сервера (`loc()`), отдельного ключа в `ui_*.json` не нужно; `LocalizationTest` зелёный. Плюс `BLIGHT_ROTSTALKER` базой `STOCK_RESIST_CHAOS: 40`. ~1 ч.
2. Строки точек очага (`blight.points[].lines` в `campaign.json`) — `+STOCK_RESIST_CHAOS` 15/20/25/30 по точкам. + рост по глубине очага, без правки шаблонов; − Матерь (не из точки) не получает, видно хуже. ~0.5 ч.
3. Только базы монстров (`leaders` + Rotstalker), рядовых не трогать. − требование «все мобы» не выполнено. ~0.2 ч.

**Макет:** нет. **Размер:** 2.5–3 ч (оба пункта). **Данные:** форма не меняется; печать — живой расчёт при броске, вайп не нужен.

## #459 — Призыв стража на карте убрать, оставить только перед заходом; пропорционально поднять цену

**Суть.** Кнопку «Призвать стража» в шапке карты убрать; призывать поверженного (отдыхающего) стража можно только в окне входа в зону. Цену поднять.

**Где сейчас.**
- Кнопка: `app/.../expedition/ExpeditionPlay.kt:312` → `GuardianSummon.kt:35-66` (Small-кнопка + `GoldCost` + `ConfirmSheet`).
- Доступ: `core/.../run/ExpeditionRun.kt:579-591` (`summon()`, `summonable`: фаза MAP, не Ваал, страж повержен, `summoned < summonsPerRun`), вид — `RunSnapshot.kt:223-226`, команда — `RunCommand.kt:65`, `RunCommands.kt:130`.
- Сервер: `CampaignService.kt:620-630` (`RunEvent.Summon`: стражу ещё отдыхать, `zone.summonable`, лимит за заход, хватает золота → списать, `SummonLog.after`, снять отдых).
- Цена — одна функция правил `ServiceRule.summonPrice` (`backend/rules/.../content/Campaign.kt:744`): `summonPerLevel × areaLevel × summonGrowth^повторы`; `campaign.json:10583`: `summonPerLevel 150`, `summonsPerRun 1`, `summonGrowth 1.5`, окно 4 ч; отдых стража `bosses.respawnHours 1` (`campaign.json:10548`).
- Окно входа уже показывает «Страж повержен · вернётся через …» (`ZoneCard.kt:286-306`, `Guardian`), но кнопки там нет (KDoc прямо: «summoning it early is the map's own bar's»).
- Правила: клиент `RULES.md:113` (шапка карты — «призыв павшего стража … под метками»), сервер `backend/RULES.md:90`.

**Как сейчас / почему игрок недоволен.** Внутри одного захода можно убить стража, тут же призвать и убить второй раз — два стража за один вход (и за одну потраченную карту). Сейчас: ур. 5 — 750 золота, ур. 70 — 10 500, второй призыв в окне 4 ч ×1.5.

**Исправлено ли.** Нет.

**Сервер.** Да: новый параметр старта `summon=true` в `POST /campaign/start` (`HeroRoute.kt:276-281` → `CampaignService.start`): проверить отдых стража и `zone.summonable(map != null)`, списать цену, `SummonLog.after`, снять `bosses[mapCode]` до постройки захода. Ветку `RunEvent.Summon` оставить в модели (старые клиенты/журналы), но отвечать `Verdict.RULE`. Поднять `API_REVISION` (101→102) на обеих сторонах.

**Варианты:**
1. **(рекоменд.)** Кнопка «Призвать · цена» в строке стража карточки зоны (`Guardian`, только когда `bossDown`), подтверждение `ConfirmSheet(gold)`, затем обычный «Войти» с `summon=true` (или одна кнопка «Призвать и войти»). Цена ×2: `summonPerLevel 150 → 300` (ур. 5 — 1 500, ур. 70 — 21 000), рост 1.5 и окно 4 ч без изменений. Из захода (`MapBar`, `RunHud.summon`, `ExpeditionRun.summon*`, `RunCommand.Summon`) — удалить. + убирает «двойного стража»; + цена в одной функции правил. − продолжение открытого захода той же зоны (`CampaignService.kt:194`) нужно отдельно: призыв = новый заход (не продолжение). ~4–5 ч.
2. Цена «пропорционально оставшемуся отдыху»: `price = summonPerLevel × level × growth^n × (1 + k·оставшаяся_доля)`, k=1 (за минуту до возврата ≈ база, сразу после убийства ≈ ×2). + честно: чем раньше, тем дороже; − цена «плывёт» в окне входа, нужен отсчёт. +1 ч к вар. 1.
3. Минимум: оставить механику, но запретить призыв, если страж убит **в этом же заходе** (`bossDown` от прежних заходов — можно). − не то, что просили. ~1.5 ч.

**Макет:** да, небольшой — строка стража в `ZoneCard` с кнопкой/ценой (3 варианта в одном HTML: кнопка в строке стража / чип-переключатель «Войти с призывом» над «Войти» / отдельный лист стража с кнопкой).
**Размер:** 4–6 ч (клиент + сервер + правила обоих RULES.md + тест `PureRulesTest.summonPriceGrowsWithRepeatsInsideItsWindow` числами).

## #467 — Баффы/дебаффы под портретами мобов: по касанию — нормальное описание с реальными числами

**Суть.** Касание значков эффектов под карточкой врага должно открывать понятное описание с числами.

**Где.** Полка врага: `app/.../arena/FoeCard.kt:252-256` — плитки **14 dp (16 dp на крупной карточке)**, зазор 2 dp. Плитка — `Tipped` (`ui/components/InfoTip.kt:46-60`): касание открывает `TipCallout` (имя, строки, «Источник», «Осталось»). «+N» — лист `EffectsSheet` (`EffectShelf.kt:500`). Вся карточка врага — `clickable(onClick = onTap)` (`FoeCard.kt:184`) — выбор цели.

**Корневая причина / как сейчас.**
1. Цель касания 14–16 dp при норме 48 dp: палец почти всегда попадает в карточку → меняется цель боя, подсказка не открывается. Это главная причина «ничего нормального по клику».
2. Тексты без чисел или с «голым» числом (`EffectShelf.kt:220-260`, `FightPalette.kt:60-77`):
   - недуги: общее описание `fight.effect.*` + факт «Сила: 30%» — без смысла («замедлен на 30%», «получает на 12% больше урона»); у шока/холода/разложения число без глагола;
   - «Запуган» (`fight.intimidated_hint`), «Метка» (`fight.mark_hint`) — только словесные подсказки, без процентов и накопленного урона;
   - баффы врага (`Натиск`, `Укрепление`…) — строки есть, только если `EffectView.lines` не пусты; у баффов вида `BuffKind` силы берутся из правил и в `lines` могут не попадать → в окне одно имя.
3. Подсказка `TipCallout` — маленькое всплывающее окно поверх идущего боя.

**Исправлено ли.** Нет.

**Сервер.** Нет (если не понадобятся новые строки словаря сервера; ключи `ui_*.json` — клиент, ru+en).

**Варианты:**
1. **(рекоменд.)** Касание любой точки полки врага (полоса во всю ширину, высота касания ≥ 32–40 dp за счёт `Modifier.minimumInteractiveComponentSize`/расширенной области над плитками) открывает `EffectsSheet` врага с прокруткой к выбранному эффекту; строки листа — с действующими числами: недуги «Замедлен на N%», «Получает на N% больше урона», «N урона/с, осталось T с, стаков K»; «Запуган» — числами правила (`{r:combat.…}`), «Метка» — накоплено N урона; баффы `BuffKind` — сила из правил. + один шаблон, бой не стоит (как сейчас); + не спорит с выбором цели. ~4–5 ч.
2. Оставить `TipCallout`, но поднять плитки до 20 dp и расширить зону касания полки; доработать тексты как в п. 1. + меньше изменений; − всплывающее окно на телефоне 384 dp всё равно тесное. ~3 ч.
3. Долгое нажатие на карточку врага — лист врага с вкладкой «Эффекты». − неочевидно, касание полки по-прежнему мимо. ~2 ч.

**Макет:** да — 3 варианта: (а) лист с прокруткой к эффекту, (б) крупная выноска, (в) вкладка «Эффекты» в листе врага.
**Размер:** 4–5 ч. **Данные:** нет.

**Вопросы владельцу:**
- Касание полки: сразу лист всех эффектов врага (вар. 1) или окно одного эффекта (вар. 2)?
- Числа писать «как в PoE» («30% замедление действий») или «было → стало» (замах 1.2 с → 1.56 с)?
