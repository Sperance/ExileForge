# Проверка Exile Forge 2.0

GitHub Actions выполняет `:core:test`, `:app:lintDebug`, `:app:assembleDebug`, `:app:assembleDebugAndroidTest`.
Затем Android 35 эмулятор запускает AndroidJUnitRunner; workflow проверяет успешное завершение набора UI-тестов и сохраняет снимки экранов.

Unit-тесты на MockWebServer охватывают весь HTTP-контракт: вход без токена и скрытие пароля в журнале, создание массивом без служебных полей, PUT только изменённых полей и DELETE без тела, отказ записывать поля сервера, серверную страницу без фильтров и клиентское сужение коллекции при фильтрации, выдачу случайного предмета выбранной редкости и категории, надевание по идентификатору экземпляра, чтение каталога сфер из категории `CURRENCY` коллекции `items` и применение сферы (адрес запроса, сообщение сервера, редкость копии и вторая копия от «Зеркала Каландры»), чтение классов и таблицы уровней, дерево навыков (граф целиком, состояние персонажа и все четыре команды с их адресами), начисление опыта и отказ от неположительной суммы, лист характеристик вместе со списками работающих и неработающих предметов, сумку, чтение возможностей из таблицы маршрутов сервера, различение 404 и прочих ошибок, отсутствие автоповтора записи и отмену чтения тела.

`ContractTest` фиксирует правила контракта: `diff` отдаёт только изменённые редактируемые поля; ни одно редактируемое поле не является служебным; экипировка проверяется по редкостям и слотам самого сервера; документ персонажа не несёт экипировки, а сумка записывается как «itemId:количество»; выпавший модификатор ссылается на описание и тир; составной модификатор декодируется с одним значением на эффект; фильтры сравнивают только записанные сервером поля; таблица сфер совпадает с `EnumCurrencyOrb` сервера, а незнакомая подкатегория показывается под названием и описанием самого документа; база предмета — фиксированные модификаторы, и тир на ней отклоняется; персонаж несёт `classId` и не несёт ни `stockSkills`, ни `params`, а класс задаётся только при создании.

`CrudScenarioTest` проверяет административный сценарий записи: полный цикл создание → чтение → изменение → пул модификаторов → удаление, очистку только собственной тестовой записи при сбое и отказ угадывать идентификатор при потерянном ответе POST.

`ItemPresentationTest` проверяет отображение: проекция экземпляра поверх шаблона не меняет шаблон, редкость копии перекрывает редкость шаблона и порча переносится в карточку, отсутствующий шаблон всё равно даёт названную карточку, выпавшие значения подписываются статами своего описания, а слоты, оружие, редкости и статы переводятся на оба языка.

UI-тесты проверяют карточку предмета, выбор со второй страницы в справочнике, панель героя (надетый слот показывает шаблон и возвращает идентификатор экземпляра, характеристики приходят от сервера, неработающий предмет помечен и называет причину), панель сфер, панель дерева навыков (выбранный узел, его вид и передача кода узла наружу) и переключение языка: `LocalizationTest` рендерит карточку на английском и подтверждает, что русский остаётся языком по умолчанию.

`ServerIntegrationTest` включается только заданием `client-server`: оно собирает закреплённый бэкенд, поднимает изолированный MongoDB replica set и прогоняет настоящий `GameApi` — вход, каталог модификаторов и тиров, создание персонажа, случайную выдачу предмета выбранной редкости и категории с проверкой, что сервер выролил по одному значению на каждый эффект описания, создание персонажа с классом из справочника, надевание предмета, который персонаж вытягивает, отказ надеть предмет не по требованиям, снятие, лист характеристик со списками работающих и неработающих предметов, начисление опыта и прокачку дерева (стартовый узел, сосед, баланс очков, отказ вернуть стартовый узел и полный сброс), применение сферы хаоса на живом сервере (сфера выдаётся в сумку, списывается при применении, редкость остаётся RARE, второй копии нет) и отказ без сферы, после которого предмет не изменился, сумку, правку шаблона и отказ записать в шаблон выпавшие значения. Перед запуском задание убеждается, что сервер публикует `POST /api/v1/characterequipment/applyOrb`, `GET /api/v1/characterclass` и `POST /api/v1/characterskillnode/allocate`.

Артефакты: `exile-forge-debug` (APK), `exile-forge-ui` (результат UI-тестов и снимки арсенала и героя), `client-server-reports` (отчёты живого теста и лог сервера).
