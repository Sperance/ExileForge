ЖЁСТКИЕ ЗАПРЕТЫ:
- Ничего не меняй в `/home/user/ExileForge` и `/home/user/ktor-bestgame` (ни кода, ни контента, ни git). Никаких коммитов/пушей/веток.
- Чтобы запускать код/тесты/симуляции: скопируй сервер к себе: `cp -r /home/user/ktor-bestgame /home/user/audit/work/<твой-ид>` и работай в копии (там можно добавлять временные тесты в `rules/src/test/kotlin/audit/` или серверные `src/test/kotlin/audit/`). Gradle: `./gradlew --offline ...` из копии. Не трогай production, не ходи в сеть кроме необходимого.
- MongoDB есть локально в /opt/mongo (можно поднять mongod на своём порту с dbpath в своей рабочей папке, если нужен интеграционный эксперимент; replica set нужен для транзакций).
- Симуляции — только реальными функциями rules (не переписывай алгоритм в Python). Указывай seed, N, параметры, теорию vs наблюдение, CI.

ДОКАЗАТЕЛЬНОСТЬ: различай «проверено кодом», «проверено тестом» (реально запущен), «воспроизведено», «проверено симуляцией», «не проверено», «заблокировано». Не выдумывай. Отделяй BUG/EXPLOIT/SECURITY/ECONOMY/BALANCE/DESIGN/CONTENT/PERFORMANCE/DATA/TEST_GAP/LOCALIZATION/ARCHITECTURE. Приоритет P0–P3 без завышения. Не считай сильный билд багом; балансные вопросы — с числами и вопросами владельцу, без решения за него.

ВЫХОД: запиши отчёт в `/home/user/audit/<NN_ИМЯ>.md` на русском. Для каждой существенной находки — карточка:
`## [ID] Название` + Категория, Приоритет, Уверенность, Подсистема, Файлы:строки, Инвариант/ожидание (цитата RULES.md), Фактическое поведение, Доказательство (минимальный фрагмент/вывод теста), Воспроизведение, Последствия, Масштаб, Варианты решения (≥2), Побочные эффекты, Регрессионные тесты, Вопросы владельцу, Рекомендация, Статус.
ID-префикс тебе задан в задании (например ITEM-01). В конце файла: какие файлы проверены, какие тесты/симуляции запущены (команда, результат), что не проверено.
Финальный ответ агенту-оркестратору: краткий список находок (ID, категория, приоритет, уверенность, одна строка сути) и путь к файлу.
