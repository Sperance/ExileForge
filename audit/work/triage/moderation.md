## #489 Окно модерации: герои раздельно с подробностями + «В сети / Был в сети» как в Telegram

### 1. Суть
(а) В 0.17.3 список модерации свели в карточки аккаунтов (`fb5fc083 feat: moderation by account…`). Владелец «всё же» хочет видеть каждого героя отдельно и с подробной информацией. (б) Присутствие «в сети / был в сети» работает неверно - сделать «идеально, как в Telegram».

### 2. Где в коде
- Карточка аккаунта и строка героя: `srv/ModerationPage.kt:231` (`AccountCard`), `:270` (`HeroLine` - только портрет, имя, тестер, класс·уровень, Мощь).
- Подпись «был в сети» карточки: `srv/ModerationPage.kt:248` → `seenText` `:543`.
- Досье, факт «В сети»: `srv/Dossier.kt:133-140` → `seenShort` `:557`; другие герои аккаунта в досье - `OtherHero` `:525` (имя, класс, уровень).
- Третий формат присутствия (карточка игрока, гильдия): `ui/components/Presence.kt:29,43` (`Presence.of`, `presenceText`).
- Сервер: `be/features/logic/moderation/ModerationList.kt:47-77,142,149` (`ModerationAccount.lastSeenAt = User.playedAt`, `ModerationHero.lastSeenAt = Hero.lastSeenAt` - уходит в ответ, клиент не показывает); досье `be/features/logic/moderation/ModerationService.kt:150,291-296` (`DossierAccount.lastSeenAt = freshest session lastUsedAt`), `DossierHero.lastSeenAt` `:174` - тоже не показывается.
- Запись присутствия: аккаунт - `be/features/data/auth/AuthSessionRepository.kt:36,74-81` (`TOUCH_EVERY = 1.hours` → `UserRepository.played`); герой - `be/features/logic/hero/HeroPresence.kt` (раз в 5 мин, `server/addons/Access.kt:84`, только команда владельца от героя).
- Порог «в сети»: `rules.json:326 onlineMinutes = 10`, `rules/.../EngineRules.kt:853 online()`.

### 3. Корневая причина (присутствие)
1. **Источник слишком грубый.** Шапка карточки и досье берут время аккаунта, которое сессия сдвигает не чаще раза в час (`TOUCH_EVERY`). Окно «в сети» - 10 минут. Игрок, который играет без перерыва, получает «● в сети» в досье примерно 10 минут из каждых 60. Остальное время он «был 40 мин назад». В карточке видно «Активен сейчас», а потом до часа устаревшей давности. Точное время героя (`Hero.lastSeenAt`, шаг 5 мин) сервер уже отдаёт в `ModerationHero`/`DossierHero`, но клиент его нигде не показывает.
2. **Карточка не знает «в сети».** `seenText` не зовёт `rules.online`: «Активен сейчас» только при давности < 1 мин, а дальше «Был 3 мин назад», хотя герой в сети.
3. **Три разных форматтера** (`seenText`, `seenShort`, `presenceText`): разные слова, разные пороги, без склонений («Был 1 ч назад», «5 д назад»), дата без «сегодня/вчера».
4. **Подпись не живёт.** `System.currentTimeMillis()` берётся при рекомпозиции, такта нет (`rememberServerNow` из `ui/components/WallClock.kt:50` не используется), сдвиг часов сервера не учитывается. Без перечитывания «Был 2 мин назад» висит вечно.
5. Мелочь: `seenText` форматирует `SimpleDateFormat` с `Locale.ROOT` без года. Через год даты будут неоднозначны.

### 4. Уже исправлено?
Нет. Текущий HEAD клиента `14607737`, сервера `edcbf2a`: код выше не менялся.

### 5. Сервер / данные
- Раздельные герои: сервер нужен, если показывать подробности (сервер героя, гильдия, дата создания, санкция, присутствие героя). Поля добавляются в `ModerationHero` с умолчаниями, это совместимо. `CollectionSchemas`, вайп и миграция не нужны. Если выбрать «плоский список героев» (вариант А), меняется страница `rows`: единица страницы - герой, а не аккаунт (`groupedPage` → обычная страница героев), и счёт «всего».
- Присутствие: рекомендуется брать время **героя** (уже есть) и для аккаунта вычислять `max(lastSeenAt героев)` на сервере (поле `ModerationAccount.lastSeenAt`, без новых записей в базу). Альтернатива - писать `User.playedAt` отдельной отметкой не реже 5 мин (как `HeroPresence`), а не сдвигом сессии. Схема данных не меняется.

### 6. Варианты
**Список героев:**
- **А (рекомендую). Плоский список: карточка на героя**, под именем - логин аккаунта (касание открывает досье аккаунта), справа присутствие героя; в теле 2 строки фактов: класс·уровень·Мощь, сервер, гильдия, создан, тестер, санкция; удалённый - серым с полосой корзины. Плюсы: каждый герой виден сразу, сортировка «по активности» честная (по герою). Минусы: аккаунт с 5 героями - 5 карточек, логин повторяется; сервер - другая единица страницы и «всего героев».
- Б. Карточка аккаунта остаётся, строки героев становятся «полными» (2-3 строки подробностей у каждого героя, присутствие героя справа). Плюсы: сервер почти не меняется (только поля), группировка сохраняется. Минусы: длинные карточки, «раздельно» - лишь наполовину.
- В. Переключатель вида «По героям / По аккаунтам» в листе фильтров. Плюсы: оба вида. Минусы: вдвое больше кода и проверок, больше всего времени.

**Присутствие (общая точка для модерации, досье, карточки игрока и гильдии):** один `Presence`-форматтер в `core` (или `rules/`) по `rules.online` + склонения `plural`, живой через `rememberServerNow(60_000)`:
- «в сети» (зелёная точка) - моложе `onlineMinutes`;
- «был(а) только что» < 1 мин после выхода из окна; «был N минуту/минуты/минут назад» < 60 мин; дальше по Telegram: «был сегодня в 14:05», «был вчера в 21:30», «был 12 окт. в 09:10» (этот год), «был 12.10.2025» (раньше);
- нет данных - «был давно» / «нет данных».
  Порог «в сети» при источнике героя (шаг 5 мин) и `onlineMinutes = 10` честен. Если оставить источник аккаунта, `TOUCH_EVERY` нужно снизить до ≤ 5 мин. Это больше записей сессий.

### 7. Крайние случаи
- Герои до появления `Hero.lastSeenAt`: 0 → «нет данных». Аккаунт - максимум героев, иначе старое `playedAt`.
- Админ смотрит чужого героя: `Access.kt:84` не отмечает - хорошо, «в сети» не загорается от модерации. Но сам админ, играя, «в сети» только при командах героя: экраны настроек и модерации героя не отмечают.
- Фоновый режим и офлайн-бой: команд нет → «был N мин назад». Это честно.
- Часы устройства врут: брать `ServerClock.offset` (`rememberServerNow`).
- Корзина в плоском виде: удалённый герой без живого документа (`ModerationHero(sanction.targetId, sanction.label…)`, `ModerationList.kt:127`) - подробностей нет, показывать «—».
- Тестировщик и модерация без прав: замок `protected` - на уровне аккаунта, в варианте А его нужно повторять на каждой карточке героя.
- Склонения: RU - 3 формы (`pluralKey`), EN - 2; ключи в `ui_ru.json` и `ui_en.json`.

### 8. Тексты
- В сети: «в сети» / «● в сети» / «онлайн».
- Давность: «был(а) N минут назад» / «был в сети N минут назад» / «N мин назад».
- Сегодня/вчера: «был сегодня в 14:05» / «был вчера в 21:30» / «сегодня, 14:05».
- Нет данных: «был давно» / «нет данных о входе» / «ещё не заходил».
- Подпись логина под героем (А): «аккаунт: login» / «login ›» / «владелец login».

### 9. Макет и размер
Нужен (3 варианта карточки героя/списка). А: 6-8 ч (клиент 4, сервер 2-3, правила 1). Б: 4-5 ч. Присутствие: +2-3 ч (общий форматтер, 4 места, склонения, такт).

### 10. Вопросы владельцу
1. «Раздельно» - это: А) карточка на каждого героя, аккаунт - подписью; Б) карточка аккаунта, но у каждого героя полные подробности; В) переключатель вида?
2. Какие подробности у героя: класс/уровень/Мощь, сервер, гильдия, дата создания, золото, бои, присутствие, санкция, версия клиента - что из этого, или всё?
3. «В сети» - по последней команде героя (точно до 5 мин) - подходит? Или считать в сети и при открытом приложении без героя (экран выбора, настройки)? Тогда нужен лёгкий «пульс» от клиента.
4. Формат давности - строго как Telegram («был сегодня в 14:05», «вчера в 21:30», дата) или в минутах/часах/днях?
5. Сортировка «по активности» в плоском виде - по герою (да/нет)?

## #490 Ответы игрокам: убрать выбор категории, вид - у каждого отчёта

### 1. Суть
В модерации отчётов («ответы игроков») в ряду чипов очередей есть выпадающий выбор вида «Ошибка / Апелляция / Жалоба / Падение». Убрать его, показывать все виды сразу, а вид - подписью у каждого отчёта.

### 2. Где в коде

### 3. Как сейчас

### 4. Уже исправлено?

Сервер не меняется: клиент перестаёт слать `kind`. Данные и схемы не меняются. В правилах клиента (`RULES.md:287` «…и в конце их ряда - вид выпадающим выбором») нужно поправить описание.

### 6. Варианты
- **А (рекомендую).** Убрать `Picker` и поле `ReportQueue.kind` (или зафиксировать null). В `ReportLine` во второй строке первой - метка вида словом цветом вида (Ошибка / Падение / Апелляция / Жалоба), значок слева остаётся цветом судьбы. Плюсы: всё видно, ноль сервера. ### 7. Крайние случаи

## #528 Корзина: полоса «очистка через» не движется + админ удаляет из корзины сразу

### 1. Суть
(а) В корзине модерации полоса и подпись «очистка через N дн.» после любых удалений выглядят одинаково и не меняются. (б) Просьба: администратор должен уметь сразу окончательно стирать героев (и аккаунты) из корзины.

### 2. Где в коде
- Полоса: `srv/ModerationPage.kt:303-312` (`TrashLine`: `LinearProgressIndicator` 3 dp, цвет `Muted` на `PanelRaised`; подпись `moderation.purge_in` = «очистка через {0} дн.»), доля - `trashShare` `:579-583` (`(now - at) / (until - at)`).
- Дни: `core/network/ModerationClient.kt:81,108-110` (`daysUntil` - **потолок** полных дней).
- Срок: модерация `be/features/logic/moderation/ModerationService.kt:493` (`trashDays = 30`), самоудаление `be/features/logic/moderation/SelfDeletionService.kt:130-135` (`selfDeleteDays = 14`); `at` = `Sanction.createdAt` (`be/features/data/moderation/Sanction.kt:101,119`).
- Очистка: только фоном по сроку - `ModerationService.purgeExpired` `:564`, `purge` `:571-593` (`ModerationWatch.kt:40`). Маршрута «стереть сейчас» нет (`be/features/data/moderation/ModerationRoute.kt:55-78`).
- Досье героя из корзины: `srv/Dossier.kt:419,429` - у удалённого героя `hero = null` → строка «Удалить» становится **удалением аккаунта**.

### 3. Корневая причина
(а) Данные, судя по коду, верные: `at`/`until` пишутся при наложении и не перезаписываются (`createdAt` хранится - кодек Mongo по умолчанию пишет значения по умолчанию). «Не движется» - из-за отображения:
1. Подпись - потолок суток: удалённый 5 ч назад герой показывает «через 30 дн.», всю первую сутки то же самое; все удаления одного дня выглядят одинаково.
2. Полоса двигается на 1/30 (самоудаление 1/14) в сутки, при высоте 3 dp и цвете `Muted` на тёмном - глазом не видно.
3. Нет такта: `System.currentTimeMillis()` берётся только при рекомпозиции, без `rememberServerNow`; часы сервера не учтены.
4. Полоса тянется от удаления к очистке («сколько прошло»), а подпись говорит «сколько осталось» - смысл противоположный, при свежем удалении полоса пустая.
Нельзя исключить и данные - нужен снимок экрана или номера санкций (см. вопросы); в коде ошибки записи не найдено.

(б) Не реализовано: очистка только по сроку.

### 4. Уже исправлено?
Нет (HEAD клиента `14607737`, сервера `edcbf2a`).

### 5. Сервер / данные
(а) - только клиент. (б) - сервер: новый маршрут `POST /moderation/purge?id=<sanctionId>` (только ADMIN, `ModerationPolicy`), повторное использование `ModerationService.purge` под теми же замками; `Sanction.purgedAt = now`, запись журнала `ModerationAction.PURGE` **с актором** (сейчас `record(PURGE, null, …)` - служба); ответ - обновлённая страница/строка. Схема данных не меняется, вайп не нужен. Новые коды ошибок - локализация на сервере (ru/en) и клиенте.

### 6. Варианты
(а) Отображение:
- **А (рекомендую).** Подпись точно и живо: «очистится через 29 дн. 22 ч», последние сутки - «через 5 ч 12 мин»; рядом дата «21.11 в 05:16»; полоса - «осталось» (полная → пустая), 4 dp, цвет `Caution`, последние 3 дня - `LifeRed`; такт `rememberServerNow(60_000)`.
- Б. Только дата очистки «очистится 21.11.26 в 05:16» без полосы. Плюсы: проще. Минусы: нет наглядности.
- В. Оставить «дн.», но округлять вниз и добавить часы только в последние сутки. Минимум кода, но первые сутки всё равно «29 дн.» без движения.

(б) Стереть сразу:
- **А (рекомендую).** В строке корзины рядом с «Восстановить» - опасная `ForgeIconButton` «Стереть навсегда» (удаление, `Hold.CONFIRM_MS`, без листа), только администратору; для аккаунта - то же на шапке (стирает всех героев аккаунта). Плюсы: быстро, привычно (`RULES.md:223` - самоудаление уже держит удержанием). Минусы: случайное удержание необратимо → шкала удержания и строка последствий.
- Б. Лист подтверждения с вводом имени героя/логина. Надёжнее, медленнее.
- В. Массовое «Очистить корзину» + по одному. Больше риска, больше кода (по одному под замками, частичные сбои).

### 7. Крайние случаи
- Самоудаление (`SELF`): `purge` вызывает `erase(hero, releaseSlot = !voluntary)` - при ручной очистке поведение со слотом должно быть тем же; копия «стёртого навсегда» самоудалённого героя (`backend/RULES.md:99`) - тоже можно стереть.
- Стирание героя аккаунта, чьё удаление - дочернее (`parentId` у героев удалённого аккаунта): в корзине их нет отдельно - стирается только весь аккаунт.
- Гонки: фоновый `purgeExpired` и ручная очистка одной санкции → под `HeroLocks` + проверка `purgedAt == null` после блокировки (повтор - успех без работы); восстановление и стирание одновременно двумя админами - перечитать санкцию под замком, снятая - отказ.
- Модератор (не админ): кнопки нет; сервер отказывает рангом.
- Почта, лоты, гильдия героя уже ушли при удалении; `erase` чистит остальное - проверить, что ручной путь идёт той же транзакцией.
- Имя освобождается сразу после стирания - предупреждать в строке последствий.
- **Попутная находка:** досье героя из корзины (`Dossier.kt:419,429`) показывает «Удалить аккаунт» вместо героя - админ может по ошибке удалить весь аккаунт. Это нужно поправить вместе: у удалённого героя - «Стереть навсегда» / «Восстановить».
- Офлайн: кнопка гаснет при `account.busy`/нет сети - как у «Восстановить».

### 8. Тексты
- Срок: «очистится через {d} дн. {h} ч» / «стирание через {d} дн. {h} ч» / «удалится навсегда через …».
- Дата: «очистка 21.11 в 05:16» / «до 21.11, 05:16» / «стирается 21.11 в 05:16».
- Кнопка: «Стереть навсегда» / «Удалить сейчас» / «Очистить».
- Последствия: «Герой и его вещи стираются без возврата, имя освобождается» / «Нельзя будет восстановить» / «Стирает героя сразу, не дожидаясь срока».
- Успех: «{name} стёрт навсегда» / «Стёрто» / «Удалён из корзины».
- Отказ (рангу): «Стирать из корзины может только администратор» / «Нужны права администратора».

### 9. Макет и размер
