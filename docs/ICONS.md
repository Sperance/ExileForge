# Иконки сервера — Exile Forge 1.11

Сервер `ktor-bestgame 0.13.0` (API revision 4) рисует набор `forge-vector` сам и отдаёт его клиентам.
ExileForge больше не придумывает картинки для игровых сущностей: он берёт их у сервера, а собственные
векторные эмблемы остаются только запасным вариантом.

## Что забирает клиент

| Запрос | Зачем |
|---|---|
| `GET /api/v1/poe/capabilities` | `icons`, `iconSet`, `iconSetRevision`, `iconSetVersion`, `iconCount` |
| `GET /api/v1/icons` | манифест: идентификатор, название, категория, палитра и адрес каждой иконки |
| `GET /api/v1/icons/bindings` | таблицы соответствий: статы, теги, классы предметов, оружие, слоты, редкости, валюты, узлы дерева, действия и статусы боя, стихии, встроенные модификаторы и базы |
| `GET /api/v1/icons/sprite.svg` | весь набор одним файлом, `<symbol id="icon-…">` |
| `GET /api/v1/icons/{id}.svg` | одна иконка; `?variant=plain` — рисунок без рамки |

Маршруты иконок публичные: JWT не отправляется, набор загружается ещё до входа в аккаунт.

## Кэш

Набор детерминирован, поэтому клиент хранит его целиком в DataStore под ключом сервера вместе с
`iconSetVersion` и `ETag` спрайта. Пока версия из `capabilities` совпадает с сохранённой, сеть не
используется вовсе. При несовпадении загружаются манифест, таблицы и спрайт; повторная загрузка
спрайта отправляет `If-None-Match` и принимает `304` как «ничего не изменилось».

Кнопка «Обновить набор иконок» во вкладке «Аккаунт» перечитывает набор принудительно. Смена сервера
сбрасывает набор: иконки привязаны к серверу, а не к аккаунту, и выход из аккаунта их не удаляет.

## Как выбирается иконка

1. Поле `icon` из ответа сервера — каталог, экипировка, предметы, узлы дерева, зоны и монстры его уже содержат.
2. Если поля нет (документ записан до появления набора), работают таблицы соответствий:
   `poeBaseId` → `bases`, `weaponType` → `weapons`, `slot` → `slots`, `subCategory`/`category` → `itemClasses`.
3. Для строк характеристик — `stats`, затем `modifiers`, затем `tags`; для модификатора в конце `modifierSources`.
4. Узел дерева: крупные и ключевые узлы — по виду, малые — по характеристике, которую дают.
5. Монстр: босс — `combat-boss`, иначе по стихии.
6. Всё остальное — `ui-unknown`.

Пустой слот экипировки тоже получает иконку: она выбирается по самому слоту.

## Отрисовка

Клиент разбирает SVG сам (`core/display/svg`) и рисует его на Compose Canvas: пути, окружности,
линейные и радиальные градиенты в координатах рисунка (`userSpaceOnUse`). Окружности превращаются в
данные пути, поэтому отрисовщику достаточно одних путей. Рамка и рисунок разбираются раздельно, и
один спрайт даёт оба вида: `framed` — с пластиной, `plain` — только рисунок (мелкие значки в строках
свойств и кнопках боя). Палитра принадлежит набору; клиент перекрашивает иконку только там, где это
осмысленно, например в пустом слоте.

## Редактирование

`icon` — обычное редактируемое поле экипировки и предметов. В форме редактора оно выбирается из
списка загруженного набора; идентификатор вне набора отклоняется до отправки запроса, а сервер
отвечает на неизвестный идентификатор `400`.

## Совместимость

Всё добавленное необязательно. Сервер без набора (`icons: false` или API revision 3) оставляет клиент
на встроенных эмблемах: карточки, слоты, дерево и бой продолжают работать без единой картинки с сервера.
